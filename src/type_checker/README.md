# Type Checker

The `type_checker` module enforces Miri's static typing rules, ensuring that expressions are valid and operations are performed on compatible types before code generation begins.

## Overview

The Type Checker traverses the Abstract Syntax Tree (AST), assigns types to every expression, and validates that all type constraints (e.g., function arguments, assignments, field accesses) are satisfied. It also performs type inference.

## Architecture

-   **Context Environment (`Context`)**: The central state object that tracks variables, functions, and types currently in scope. It handles lexical scoping by pushing and popping environments as the traversal enters and leaves blocks.
-   **Validation Passes**: The checker validates declarations top-level constructs, statements, and deeply inspects expressions.
-   **Type Inference**: For variable declarations without explicit types (`let x = 42`), the type checker infers the type from the right-hand-side expression.
-   **Type aliases (`statements/mod.rs`)**: `type X is T` is registered before declarations are collected — once after type shells exist and again as the statement is reached among the declarations — whenever `T` already resolves, so a class method signature can spell `X`. The body pass (`check_type_statement`) re-registers it and reports its errors.
-   **Type shells (`mod.rs` `collect_type_shells`)**: Every class, trait, struct and enum of a module is registered as an empty shell, its type parameters named but unbounded, before any bound is read; the bounds of every shell are resolved only once all of the module's shells exist (`resolve_shell_bounds`). A bound may therefore name a type declared further down, as a field type or an `implements` clause may.
-   **Type definitions (`statements/type_definitions.rs`)**: Every trait, then every struct, then every enum, then every class, of a module is defined — a trait's parents and method signatures, a struct's fields, an enum's variants and method signatures, a class's fields, method signatures and hierarchy — before any body of the module is checked; the body pass then checks only the traits' default bodies and the enums' and classes' method bodies. A free function or a method written above a type can therefore call its trait's methods, read its fields, construct it, build its variants and match on them, and a class written above a trait it implements is checked against the trait's methods. A trait, struct, enum or class shell is told apart from a duplicate declaration by `pre_registered_types`, which the definition claims.
-   **Generics (`generics.rs`)**: Handles substitution and validation of type parameters for generic functions and collections. A parameter written as a trait or base class binds from the arguments the argument's own `implements`/`extends` clauses pass it.
-   **Generic methods (`generics.rs` `with_member_generics`, `context.rs` `MethodInfo::generics`, `expressions/access.rs` `method_generics`)**: A method of a class, trait or enum may declare its own type parameters, `fn m<T>(x T) T`. They are defined in a scope of their own while the method's signature is resolved, and kept on `MethodInfo::generics` in declaration order; one named after an owner's parameter is refused (`MER_TYP_064`, `hidden_types.rs`). The method's function type carries them with their bounds read at the receiver's type arguments, so a call binds them as it binds a generic function's: `call_generic_mappings` holds what the call binds, written type arguments (`b.m<int>(5)`) included, and the bounds and the requirements the body states of them are answered at the call. A generic method is never given one body shared by every type argument. Called through a value of a trait type it is refused (`MER_TYP_087`): a vtable slot holds one body; through a type parameter bounded by the trait, or `self` in a body compiled per class, it is accepted. A call through a bounded parameter states `Obligation::GenericMethodCall` on the instantiation-requirements rail, and a site binding that parameter to the trait type itself is refused there with the same code. A constructor or a drop hook declaring type parameters is refused (`MER_TYP_088`): building or releasing an instance binds none.
-   **A trait's `Self` (`trait_self.rs`, `context.rs` `current_self_type`)**: Inside a trait, `Self` and `self` are `Generic("Self", implements <the trait at its own parameters>)`, a parameter every trait declares implicitly; inside a class or an enum they are that type. `current_class_type` keeps naming the trait itself, so a trait's own name written in its body is a value of the trait type. `mentions_self` is the one answer to whether a type names `Self`, read by conformance (`class_def.rs`, which substitutes `Self` with the class at its own parameters wherever it is nested, so a parameter typed as the trait may not be narrowed), by the inherited-return rule (`inherited_traits.rs`), and by the refusal. A member a trait declares, read off a receiver, has its `Self` pinned to the receiver on the declared signature, in the same substitution that reads the trait's parameters at the receiver's arguments (`pins_at_receiver`, with `pin_self` and `read_self_at` the only other readers of `Self` at a type): a class is itself, a bounded type parameter is that parameter. A value of a trait type does not meet a bound on a trait with a member needing the class (`misses_bound_for_its_class`, read by `argument_meets_bound`), and an operator obligation reaching such a value at an instantiation is refused at the site. Through a value of a trait type a member with a parameter naming `Self`, or a result naming it inside another type, is refused (`MER_TYP_089`), as is an operator whose method takes `Self` (`==` on two `Equatable` values); a bare `Self` or `Self?` result reads as the trait value. A trait default's calls on a `Self`-typed receiver are recorded on the instantiation-requirements rail under `SELF_PIN`. An abstract class keeps its own type as `Self`.
-   **Call instantiation (`call_instantiation.rs`)**: Decides which instantiation of a generic function a call reaches — from the type arguments it writes out, the values it passes, and, for a parameter only the return type mentions, the type of the location its result is stored in. A call nothing binds is refused at the end of its statement; lowering never links a generic call to the shared body.
-   **Binding refinement (`binding_refinement.rs`)**: A local binding written without a type takes its initializer's type, which a variant constructor leaves open in the arguments its payload does not name. When a later store into the binding (an assignment, an index store, a call such as `push` on it), or a read of it where a type is expected, binds one of those arguments, the use records the binding's refined type and the function body is checked again, with the declaration taking the refined type as if it were written. A binding at module scope is still refused.
-   **Type sets (`type_set_shorthand.rs`, `utils.rs` `resolve_type_set`, `compatibility.rs` `is_within_type_set`)**: `type Real is f32 or float` is an alias whose template is `TypeKind::OneOf`. A set is refused as the type of a value in `resolve_type_expression` unless the resolution is a bound or a `type` target (`resolve_bound_type`), and an `is` bound naming a set holds for each member, or for a caller's parameter whose own set lies within it. A set written in a function signature (`fn sin(x Real) Real`) is rewritten, before the module is checked, into one type parameter per set name (`'Real`), so later phases see an ordinary generic function.
-   **Bound lists (`ast/bounds.rs`, `generics.rs` `resolve_bounds`, `bound_list.rs` `validate_bounds`, `compatibility.rs` `argument_meets_bound`, `expressions/access.rs` `bound_declaring`, `hidden_types.rs`)**: a type parameter carries its bounds on itself, `TypeKind::Generic(name, Bounds)`, an ordered list of keyword-and-type pairs (none, one, or several joined with `and`); a bound list is never a type of its own. `resolve_bounds` is the one place a written list becomes `Bounds`. An argument meets the list when it meets every bound (`argument_meets_bound` judges each, the one authority), a parameter bounded by several meets a single bound when one of its own does, and a refusal names the first bound missed (`missed_bound`). A member read on such a parameter is looked up, typed and dispatched through the bound that declares it (`bound_declaring`, which MIR lowering reads too); the narrowing is for the lookup only, so the member's `Self` is the parameter with every bound, and a member no bound declares is refused naming all of them. `resolve_bounds` validates each declared list once, in `bound_list.rs` `validate_bounds`: a repeated bound, a type set beside another bound, a second class, and two bounds declaring one member with different signatures are refused where the list is written (`MER_TYP_037`). A parameter extends another through any `extends` bound of its list (`compatibility.rs` `bound_reaches`). A type parameter named after a type the declaring module sees is refused where it is declared (`MER_TYP_064`); what a module sees is its own scope (`module_loader.rs` `current_module_sees`): the types it declares, those its own `use` lines and the prelude bring in, and the built-in `Option` and `Linear`, never a type only another module reaches, with help spelling the `and` form when it hides a trait written after a bounded parameter.
-   **Numbers of different types (`ast/types.rs` `common_numeric_type`, `holds_every_value_of`)**: an operator between two integers or two floats computes at the narrowest type holding every value of both on every target (`int`/`float` are 64-bit on the host, 32-bit on a GPU); a store requires the destination to hold every value of the source. A literal, or an untyped `const` or `let` bound to one, takes the other operand's or the destination's type when its value fits (`binary.rs` `number_at_width`, `int_literals.rs`, `float_literals.rs`); each use takes its own width, and MIR lowering converts the stored binding at the read. Arithmetic built only from such numbers takes a width as one number when every value it computes fits (`source_arithmetic.rs`); a `var` takes its width once, at declaration. A generic body types an operator with a parameter operand as the parameter's type; each instantiation checks the promoted type agrees, with a literal operand flagged on the requirement so it adapts there too. MIR lowering spells out the operand conversions codegen's own widening cannot (a sign change, or a result wider than both).
-   **Hashing (`operators.rs` `type_lacking_hash`)**: Every value answers `hash()`. A type whose equality is derived derives its hash from the same parts; a type that writes its own `equals` must declare `hash` beside it, and is refused (MER_TYP_079) as a set element or map key and wherever its `hash()` is called. A body hashing a value of one of its own parameters states `Obligation::Hash`, answered where the parameter is pinned.
-   **Derived conformance (`derived_conformance.rs`)**: A class meets the traits it declares; every other type — a number, `bool`, a struct, an enum, a tuple, an optional — meets an operator trait (`Equatable`, `Comparable`, `Addable`, `Multiplicable`, `Hashable`) wherever the operator that trait stands for applies to it, judged by replaying the checker's own operator check, and `Accelerable` wherever `is_accelerable` holds. A bound is met that way (`check_implements`), and the trait's method is typed on such a value as the operator it is (`derived_member_type`).
-   **Body writes (`body_writes/`)**: One walk records every mention of a binding in a body and the role of the path it starts (assigned, receiver of a call, argument of a call), and both write verdicts are read off it. **Parameter writes (`body_writes/parameters.rs`)**: which parameters each function, method, nested function and closure writes — a mention that is the target of an assignment, the receiver of a method that writes a built-in collection receiver, or an argument a runtime entry point writes in place (a cast is not followed) — keyed by the parameter's type expression, so MIR lowering only binds copies (`mir/lowering/written_parameters.rs`). **Receiver writes (`body_writes/receiver.rs`)**: Which methods write their receiver, read off their bodies once every module is checked, so MIR lowering copies a shared collection before calling one and no method of the standard library is named in the compiler. A body writes its receiver when it hands `self`, or a cast of it, to a runtime entry point at a position its `runtime` declaration does not state it only reads; assigns to an element or field of `self`; calls on `self` a method that writes it, or on `super` a method whose body in the parent chain does; or uses `self` any other way — binds it, casts it outside a runtime call, hands it to a function or another value's method, or captures it in a closure — since a runtime entry point writes the block it is handed in place. Indexing `self`, reading a field, comparing, formatting, iterating over or returning it only reads it. Calls on `self` are followed through the class's own methods and the default bodies its base classes and traits supply, nearest first, to a fixed point. A call of a method with no body the class can reach is taken to write, and so is any method of a class the pass never analysed, so the lookup fails closed: a needless copy costs time, a missing one loses a write or frees a block another binding holds. A unit test pins the derived writers and readers of the standard library's collections. **Held operands (`body_writes/held_operands.rs`)**: Operands are evaluated left to right and each yields its value at the moment it is evaluated, but lowering reads an operand that names a place only where the call or operator consuming it runs. The same walk records every expression that evaluates operands in sequence (a call with its receiver, an operator, an index, a range, an array, tuple or variant literal; a list, set or map literal stores each element as it is evaluated and is none), and an operand that is a place is held — read into a temporary on the spot by `mir/lowering/sequencing.rs` — when a later operand of the sequence may write it: hands a binding the place is read through (its root or an index binding along it) to an `out` parameter, assigns it, calls a method that writes it as a collection receiver or hands it to a runtime entry point that writes it in place; or, for a place reached through a value that may be shared by reference (`reference_sharing.rs`: a class, a trait some reference class implements, a type parameter), runs any call but an intrinsic or a variant constructor, an operator a class answers, or any assignment. Such a place may start at a call's or a conditional's result. No step of a path an assignment or a call writes is a sequence of its own, so a hold never redirects a write into a copy. The walk lays each expression's records out as a run of positions, so a sequence costs only its own operands. Ordinary code holds nothing, so it pays no copy. Parameter writes and held operands read one walk per declaration. **Reference sharing (`reference_sharing.rs`)**: whether the values of a type are shared by reference, a value, or may be either — a class unless its `extends` chain reaches a copy-on-write collection or `String`, a trait by what its implementing classes agree on; MIR's local-borrow pass reads it as well.
-   **Lost capture writes (`body_writes/capture_writes.rs`)**: A closure or nested function holds a copy of each value it captures, so a write to one would be lost when the call ends and is refused (`MER_TYP_090`). The checker records which mentions are of a captured binding while it resolves names (`Context::captured_binding`, the scopes being its own), and this pass applies the one rule of what writes (`is_written`) to those mentions, after every body is checked, when `ReceiverWrites` is known. A write with a class instance or trait-typed value on its written path (`holds_by_reference`) reaches the object and is allowed.
-   **Reference cycles (`reference_cycles.rs`)**: Reference counting never frees a cycle, so a store that puts an object back into one of its own fields is refused (`MER_TYP_081`): a store into a place rooted at a class or trait binding whose value is that binding, a closure capturing it (`ast/captures.rs` `collect_lambda_captures`), or a variant, constructor call or literal holding one of those. A built-in collection, which copies on write, or a struct is a value, so a store into it closes no cycle. Only the direct form is seen; a cycle through another name or object is not.
-   **Value demands (`value_demand.rs`)**: A `void` result is not a value. `infer_expression` refuses, through one list of the operands each expression form reads, any operand that produces none; a binding's initializer and a returned value ask the same check. A branch of an `if` or `match` read as a value is examined one by one, because a void branch is skipped when the joined type is worked out.
-   **Type mismatches (`type_mismatch.rs`)**: Every error that compares two types (MER_TYP_002, 029, 039, 051, 063) goes through `report_type_mismatch`, which takes the expected and found sides (`TypeSides`, spelled as source spells them) and a help naming the fix; the diagnostic carries both sides as structured fields. `tests/diagnostics/type_error_structure.rs` refuses any other way of raising those codes. `atomic_buffers.rs` words the atomic-buffer refusal for both the checker and lowering.
-   **Instantiation requirements (`instantiation_requirements.rs`, `used_methods.rs`, `compiled_instances.rs`)**: A generic body states what it requires of its parameters, and each place the program uses the body at concrete arguments answers those requirements by replaying the body's own checks there — a call, a construction, an element sort or set lookup, a conversion to a trait. After lowering, the pipeline answers every instance it compiled once more through `compiled_instance_refusals`, so a body lowering reaches in a way the checker did not foresee is refused rather than compiled unchecked, or, when only a vtable slot or an element thunk names it, withheld.
-   **Reached instantiations (`reached_instantiations.rs`)**: A generic body records each generic class it builds from its own parameters (`Box<T>(x)`). Once every pinning site is settled, the bodies the program reaches are followed from each site pinning a body at concrete types, through the sites each reached body writes, and every class a reached body builds is recorded in `reached_class_instantiations` at the types it is reached at. Whether a trait or a base class is a resource, and which copies of a generic class's method a refusal names, are then decided over those and `generic_class_instantiations` together (`ownership_instantiations`), whichever body builds an instance. A site a trait slot reaches is followed only where lowering compiles the slot's body: where the call through the trait still agrees with the converted trait's arguments at the types the converting body is reached at, and where the method's obligations hold at the instance. Lowering still finds what it compiles on its own and never reads the reached set. Every reached body is followed, deepest first, within the bounds of `instantiation_limits.rs`; a body or built class past a bound that a recursion leads to is refused as polymorphic recursion (MER_MIR_016), with the text lowering gives, and the chain of reached bodies is the growth chain the refusal names (`reached_instantiations/limits.rs`).
-   **Instantiation limits (`instantiation_limits.rs`)**: The one specification of how far generic instantiation may grow: the depth and size bounds on an instance's type, the bound on value instances per class, the shape measures over a type, and the polymorphic-recursion refusal with its growth chain. Lowering reads it to refuse an instance past a bound, so its text is the same whichever stage asks.
-   **Iteration plan (`iteration_plan.rs`)**: `iteration_plan(ty)` is how a `for` loop walks a value. `check_for` asks it once per loop and records the answer against the `for` statement (`record_iteration_plan`); lowering reads that record (`recorded_iteration_plan`) and never asks again. A list, array or tuple, which the language indexes itself, and a class implementing `Indexed` are walked by position (`IterationPlan::Indexed`); any other class reaching `Iterable` is walked through its iterator (`IterationPlan::Protocol`). It is keyed on the traits, never on a collection's name. An iterator is declared as the trait `Iterator<T>`; the class behind it is the one every value an `iterator()` body returns is an instance of, which the checker notes while checking that body (`note_returned_value`; only the method's own returns, not a lambda's). Every class's `iterator()` body is checked before any other body of its module (`check_iterator_bodies`), so a loop anywhere in the module reads a complete note whatever order the classes are declared in. Once every class of the program is known, `settle_iteration_plans` drops the noted class from a plan when a subclass of the walked class overrides `iterator()` to return another, so the loop calls `next` through the trait. A known class shows whether the iterator implements `Entries`, whose `value()` a second loop variable reads; a second variable over an iterator not shown to implement it is refused (MER_TYP_030, the code the loop-variable count already uses), and so is an iterator loop in device code, which has no heap for the iterator (MER_TAR_008). `check_for` records the methods the loop runs (`used_methods.rs` `record_iteration_method_sites`) and the iterator's instantiation, as `record_stepping_method_sites` does for a stepped range. A class owing `Iterable`'s `iterator` while it declares `length` and `element_at` is told to implement `Indexed` instead (MER_TYP_057); a trait default from one listed trait meets a method another listed trait only requires. A value typed as the `Iterable` trait, or as a parameter bounded by it, is not walked yet (`refuse_not_iterable`).
-   **Visibility Verification**: Enforces access control (`public`, `private`, `protected`) for class fields and methods across module boundaries.
-   **Hygiene (`hygiene/`)**: Reports what a file declares and never uses — an unread local, a parameter no body reads, an unused import, an uncalled private declaration — and statements written after a `return`, `break` or `continue`. Every report is a warning, because each names something the program would mean exactly the same without. It runs over the file being compiled and nothing else: an imported module is somebody else's file, and its private helpers are called from inside it.

## Design Principles

1.  **Multiple Errors**: Like the parser, the type checker is designed to report as many type errors as possible in a single run, utilizing a unified diagnostic system rather than failing immediately upon the first error.
2.  **Non-Destructive AST**: The type checker does not heavily mutate the AST. Type information necessary for later stages (MIR lowering) is either stored in a sidecar data structure (the Context) or annotated minimally.
3.  **Strictness**: It strictly enforces type compatibility, trait constraints, and OOP inheritance rules, guaranteeing that well-typed Miri programs will not encounter runtime type exceptions.
