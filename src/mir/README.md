# Mid-Level Intermediate Representation (MIR)

The `mir` module defines the Mid-Level Intermediate Representation, a Control-Flow Graph (CFG) based representation of Miri programs used for advanced analysis and optimization.

## Overview

While the Abstract Syntax Tree (AST) represents the syntactic structure of code, it implicitly encodes control flow (like loops and branches). MIR flattens this structure into explicit jumps between Basic Blocks, making dataflow analysis, optimization, and code generation much simpler.

## Core Concepts

-   **Basic Block (BB)**: A linear sequence of statements with a single entry point and a single exit point (a `Terminator`).
-   **Terminator**: The instruction at the end of a block that dictates control flow (e.g., `Goto`, `SwitchInt`, `Return`, `Call`).
-   **Locals (`_0`, `_1`, etc.)**: All variables and temporaries are flattened into an indexed array of Locals. `_0` is always the return value.
-   **Places and Rvalues**: Assignments take the form of `Place = Rvalue`, meaning a computational result (`Rvalue`) is written into a memory location (`Place`).

## Architecture

-   **Lowering (`src/mir/lowering/`)**: Translates the checked AST into the MIR format.
    -   **Receiver copy on write (`method_dispatch.rs` `prepare_method_self`)**: A method call on a built-in collection whose method writes its receiver, as the type checker's `ReceiverWrites` reads off the method's body, first hands the receiver to the collection's copy-on-write entry point (`runtime_fns::cow_fn`), so the call writes a collection only that binding holds. A receiver reached through a field, a tuple element or a collection element is unshared along its whole path instead (`lowering/expression/unshare.rs`), the tuple holding it included. So is a receiver no binding holds — a call's result, a getter's, a conditional's, or a field or element of one: it is held in a temp owning one reference, unshared like a binding's value, and released once the write is done, so the write never reaches what the value was read from. Every writer goes through one bracket (`written_receiver.rs` `lower_pending_receiver`, `method_dispatch.rs` `with_mutated_receiver`), the intercepted `push`, `insert`, `set`, map `set` and set `add` included, so each releases that temp exactly once. The bracket lowers the receiver's path — the value it starts at, its indexes and keys — then the write's other operands in source order, and makes the receiver the write's own only after them, right before the write: an argument that hands the receiver's value to another name (a method storing it, a closure capturing it) does so before the check, which then copies it, so no code runs between a check and the write it covers. A compound map store `m[k] op= v` lowers its path and key, then its right-hand side, then reads the old value from the map the path names at that point (as an indexed list's compound store does) without checking it, combines, and only then makes the map its own and stores. Inside such a method `self` is then held by the caller alone, so a write the body makes on the whole of `self` only checks that it arrived so (MER_RT_017 otherwise) and copies nothing.
    -   **Written parameters (`written_parameters.rs`)**: A collection, struct or tuple a caller passes is a value the caller keeps, so a function never writes the parameter itself: a body that writes one — a writing method called on it or on a path starting at it (`method_dispatch::is_receiver_written`, the rule `prepare_method_self` applies to the call), a runtime entry point handed it, or a path starting at it, at a position it writes in place (`runtime_fns::writes_in_place`), or an assignment to it or through it — is lowered as if it began with `var <name> = <name>`. The writes are read off the body before it is lowered (closures and nested functions are bodies of their own), so every use of the name, a loop header lowered before the write included, reads the copy; the copy is bound in bb0, ahead of parameter guards, where `optimization/owned_params.rs` can turn it into a move of a parameter every caller funds. A method's receiver and an `out` parameter (the caller's binding itself, whose paths `unshare.rs` unshares like any binding's) are never copied, and `Body::receiver` names the receiver. A write that still reaches a lent parameter — a form the scan missed — is an internal error in `unshare.rs` `root_step` and `method_dispatch.rs` `emit_cow_check`, and `verify/parameter_writes.rs` checks under `--verify-mir` that no store has such a parameter as its root and that no runtime entry point is handed one, whole or projected, at a position it does not only read (`runtime_fns::only_reads_argument`) other than an element it stores — which covers a uniqueness check, a copy-on-write call and a write the runtime makes in place. A call to a runtime entry point is a write like a writing method's: each argument it writes in place is lowered as a writing method's receiver is (`lowering/runtime_writes.rs`, through `written_receiver::lower_pending_receiver`, made the call's own after every argument is lowered), so a whole binding is copied on write, the body's own receiver is checked, and a path has every value on it unshared. A method's receiver arrives as its own, so a write through the whole receiver is preceded by `runtime_fns::rt::RECEIVER_UNIQUE` (`method_dispatch.rs` `emit_receiver_unique_check`) rather than a copy-on-write: the call only reads the count and stops the program with MER_RT_017 when it is not 1, since a copy would release a reference the method never held. It is not a sharing question, so the passes that answer or hoist those leave it alone; the verifier flags a receiver of a copied-on-write type that is still copied on write, asked whether it is shared, or replaced whole. Lowering's write path and the scan read a path's shape through one function (`unshare::path_links`), and which values copy on write is one rule both lowering and the verifier ask (`type_facts::unsharing`).
    -   **Instance demand (`instance_demand.rs`, `vtable_demand.rs`)**: Which methods of a generic class instance are compiled. A method a lowered body calls by name is compiled at its instance; one only a vtable slot or a container's element thunk names is compiled only where the checker's obligations hold there (`ImpliedMethodVerdicts`), and withheld elsewhere, its slot filled with the runtime trap. `vtable_demand.rs` decides which slots a program reads at all.
-   **Instantiation algebra (`src/mir/instantiation/`)**: The one home of the rules for generic instantiation that lowering and codegen share — what a written type argument denotes, how a substitution rewrites a type, the type a member (a field or an enum payload) has at an instantiation (`member_type_at`, `field_types`), which arguments get a per-instantiation body, (`shape.rs`) a type's constructor parts, how deep an instance nests and which parameters it leaves open, and (`inherited.rs`) what a class inherits at an instantiation through its `extends` chain. Lowering re-exports these under its old paths.
-   **Dispatch data (`src/mir/dispatch/`)**: The settled shape of dynamic dispatch as data: the shared `VtableLayout`, the `VtableInstance` a constructed instance points at, the `VtableFills` each vtable is written with, and the methods a container asks of its elements. How a slot's target is resolved stays with lowering's method dispatch.
-   **Type facts (`src/mir/type_facts/`)**: The read-only `TypeFacts` the pipeline builds once lowering has settled every instantiation and hands to the CPU backend — the one seam through which codegen reads the program's types (a `make audit` gate and `tests/codegen/layer_boundary.rs` keep codegen from naming the type checker or MIR lowering). It holds the type definitions (re-exported as data), the method-body instantiation registry and the vtable fills, and answers the rules the backend needs by delegating to their one implementation: a field's type at an instantiation, a type's drop hook and `clone`, the traits it implements and the methods a container asks of its elements. `drop_instantiations.rs` settles the separate set of instantiations a drop thunk is emitted for: every concrete instantiation a compiled host body holds (locals, closure captures, struct and class constructions, aliases read through), closed over the fields and payloads those store, refused as polymorphic recursion when a field nests its own type past the instance depth bound.
-   **Residency readbacks (`src/mir/residency/`)**: A required pass, run on every host body after lowering and before Perceus, that reads a `gpu`-resident binding's device buffer back into its host array before each host read that could otherwise see stale values. A forward dataflow tracks, per device handle, whether the host array may lag the device: a read every path reaches behind reads back unconditionally, a read only some paths reach behind (the first read in a loop after a launch) tests a flag the pass keeps for the handle, and a read no path reaches behind gets nothing. Each readback first gives the binding a host array of its own, so earlier host copies keep their values. `verify::verify_cross_residency_readback` independently checks the result under `--verify-mir`.
-   **Equality and hashing (`lowering/expression/structural_equality.rs`, `structural_hash.rs`)**: `==` on a struct, enum or optional is lowered to a walk over the parts it compares, calling the `equals` a type declares where it has one. `x.hash()` on a type that declares no `hash` is lowered (`lowering/derived_hash_call.rs`) to a mirror walk over the same parts, so two values `==` calls equal hash alike; an operator method a non-class type answers through its operator (`lowering/derived_operator_call.rs`) is lowered as that operator — `equals` as `==`, `concat` as `+`, `repeat` as `*`, `compare` as `(a > b) - (a < b)` over operands evaluated once; a kind `==` compares as one machine word hashes that word. A set or map matched through an `equals` callback is also handed a hash callback: `dispatch::element_hash_symbol` names one per element type, the pipeline lowers it from the same walk (`lowering/element_equality.rs`), and codegen registers it beside the equality.
-   **Optimization (`src/mir/optimization/`)**: A suite of passes (`SimplifyCfg`, `ConstantPropagation`, `CopyPropagation`, `DeadCodeElimination`, `Perceus RC`) that transform and optimize the MIR inplace.
-   **Owned parameters (`optimization/owned_params.rs`)**: A call lends its managed arguments by default — the callee reads the caller's reference and never releases it. Run once over the whole program after the residency readbacks and before Perceus, this pass makes a parameter *owned* when its only use is one binding in the entry block — to a local (`var items = start`), or a store into a field declared at its type (`self.items = items`) — apart from copies an expression statement discards, which go when the parameter is taken over. Everything else stays borrowed: a method's receiver; an `out` parameter; a vector, which a collection stores inline; a gpu-resident buffer, as the parameter or as the binding; a type whose release may run a drop hook anywhere inside it (`mir::type_facts::DropHookReach` — elements, options, tuples, fields, payloads, any subclass, and conservatively every trait-typed value, closure and type parameter), since owning it would move where the hook runs; a type naming a type parameter; a binding that dies in the entry block, which costs nothing borrowed; a body whose entry block a branch returns to, where the binding would run more than once; and any function that is not a plain top-level host function or method compiled for one instantiation, is a body a vtable slot points at (`VtableFills::slot_symbols`, added to the compiler-synthesized callers) or a method a runtime thunk calls at every instantiation (the drop hook and the element methods), is captured into a closure, is named as a value, is called from a GPU body or a compiler-synthesized caller, is called at another arity, is never called, or is lowered into more than one body. The binding becomes a move out of the parameter, `Body::owned_params` records it, and every call to the function passes that argument `ArgMode::Owned`. Perceus retains each owned argument before the call and does not retain the parameter in the callee; RC elision cancels that retain against the caller's release of a local that dies right after the call, so a callee writing its binding finds it unshared and writes in place instead of copying. `--verify-mir` tracks an owned parameter from one reference on entry, consumes an owned argument at the call, and checks across the program that every call's modes match its callee's `owned_params`, and that a function taking a parameter over has one body, is named only as a call's callee and is called by no GPU body.
-   **Dying sources (`optimization/rc_elision.rs`)**: A copy of a whole local that dies right after it — the value itself, a rebinding's value, or one operand of an aggregate such as `Some(x)` — is funded by a retain only for the local's own release to give back. When the first mention of the local after the retain is that copy, the next is its release with nothing else released in between, and the one after is the end of its storage or a rebinding not reading it, all in one block, the pair cancels and the copy becomes a move: the destination takes the local's reference over. A local a borrow reads from or that borrows is left alone. `--verify-mir` reads a bare-local `move` operand of an aggregate (not one laying vectors out inline) as the aggregate taking that reference over; a retain before such a store pays for the local itself.
-   **Heap effects and lent field arguments (`analysis/heap_effects.rs`, `optimization/lent_arguments.rs`)**: A lent argument read through a class field or a dereference (`h.node`, `self.items`) is held only by that field, and a callee reaching the instance another way can replace or empty it while it still reads the argument. Run once over the whole program right after owned parameters are decided, `heap_effects::stamp_quiet_calls` classifies every operation as *loud* — it may release a heap value another name holds — or *quiet*: a store crossing a class field or a dereference, or rooted at the receiver, an owned or `out` parameter or a capture; a runtime call that may call a closure, or writes in place (`runtime_fns::writes_in_place`) an argument holding counted contents that is not a whole counted local the body owns, or one whose release may run a drop hook; a virtual call, a closure call, a kernel launch, a call to a symbol with no body; and a release that may run a drop hook (before counting: the end of a local's storage or a rebinding of such a type; after it: its `DecRef`) are loud. Copy-on-write, count questions and retains are quiet. A call to a function of the program is as loud as its callee, decided by a least fixpoint from every body quiet, so recursion among quiet bodies stays quiet. The pass records `Body::quiet_calls` and `Body::unique_receiver_calls` (a callee whose body writes its receiver in place as a value its caller copies on write, which the caller made unique for it; a receiver it only reads, as `map` or `filter` do, is not exempt) by the block each call ends. Perceus then reads every lent counted argument crossing a class field or a dereference, or holding an entry a runtime getter borrowed from a collection reached that way (`m[k]` on a map field), that a call not recorded quiet is handed — a direct call into the program, a virtual call or a closure call; never a runtime call, and never a receiver the callee writes in place (it stores through it, or hands it to a runtime writer or uniqueness check), which its caller made unique — into a temporary before the call, retained like any copy of a counted field, whose storage ends where the call returns. `--verify-mir` works out the quiet calls again over the counted program (`verify/lent_arguments.rs`) and reports any such argument still lent unretained.
-   **Borrowed locals (`optimization/local_borrows.rs`)**: Run inside Perceus, before it places any retain. A managed local defined only by copies of a projected place reached from a counted local the body owns, or a counted parameter (lent, taken over, or the receiver; never an `out` parameter, a capture or an address-taken local), through value steps (an element of a `List` or `Array`, a field of a struct, tuple or optional, an enum's payload) and fields of class instances — never a dereference — borrows what it reads, the way a body borrows a parameter: no retain at the read, no release at its `StorageDead`. A read through a class field or out of a parameter is one other code may reach (a method can clear the field, a caller's other holder can empty the list, without naming the root), so such a borrow, and every borrow read out of one, is also refused when its range holds any operation `analysis/heap_effects.rs` finds loud (`BodyNoise`): a loud statement, a virtual or closure call, a loud runtime call, or a call to the program not recorded in `Body::quiet_calls`. The rule ignores which value an operation touches, so an alias of the root changes nothing; the end of a lent parameter's binding is no change, since its caller's reference holds the value. An entry a runtime getter lends out of a collection (`runtime_fns::hands_back_a_borrow`, `m[k]` on a map; listed by `heap_effects::borrowed_entries`) holds no reference of its own, so a borrow read out of it also counts the locals holding the collection among its owners and is always treated as reached by other code. It must run no drop hook and hold no device buffer, and must never be rebound, released by hand, made a call's result, merged in a phi, handed to a runtime entry point that keeps it or asks whether it is shared, or passed `out`. Unless its type is a reference by design (a class, or a trait some class implements and only reference classes do), it must never be written through, nor handed to any callee other than a runtime entry point that only reads it (`runtime_fns::only_reads_argument`, an allow-list) — except that a value a write copies (`type_facts::unsharing::is_copied_on_write`) may be lent whole, by copy, to a function of the program or to a method past its receiver, since a body writing such a parameter binds a copy of it on entry that takes a reference of its own (`lowering/written_parameters.rs`). A method's receiver gets no such copy: a write through it relies on the caller's copy-on-write or on `RECEIVER_UNIQUE`, which a borrowed value's count — its owner's — would answer wrongly. A closure call, a virtual call, an owned or `out` argument and a value of any other type (a string, an optional, an enum) are refused. On every path from a definition to the end of its storage — reaching the body's end first refuses it — its root, and a borrowed parent's owners for a borrow read out of another, is only read through a projection, retained through one, or lent by copy to such a reader. Escapes stay funded as for a borrowed parameter: a copy into a store, a return, an aggregate or a capture, a move, and an owned argument are each retained. `Body::borrowed_locals` maps each borrow to every owner keeping what it holds alive; RC elision never cancels an owned argument's retain against a borrow, never elides the retain of a local a borrow relies on, and never elides a pair copying a borrow. `verify/local_borrows.rs` checks every record again from the final MIR under `--verify-mir`, with its own access classification — a record that holds leaves the local untracked, one that does not is a violation; the step-reach and reference-by-design predicates are shared with the inference. For a borrow other code may reach it applies the heap-effect rule over the counted body, with the quiet calls the pipeline works out again over the counted program (`verify_body_with_quiet_calls`), never the stamped ones; with none, every call to the program counts as loud.
-   **Index numbering (`optimization/index_numbering.rs`)**: Lowering computes an index written as an expression (`l[i + 1]`) into a temp of its own at every use, so two writes to one element reach it through two places. Run just before unshare check elision, this pass renames every index through a temp to the earliest temp holding the same value: a temp written once by arithmetic on locals and literals, whose storage and address the body never touches and none of whose operands has its address taken. A forward must-analysis carries the temps whose expression still has their value; a write to an operand, or a change of its storage, removes them.
-   **Loop unsharing (`optimization/loop_unsharing.rs`)**: Run after index numbering and before unshare check elision. For each natural loop with a block that hands a whole collection local to its copy-on-write entry point on every iteration (it dominates every back edge), and that writes the local no other way than by those calls' write-backs, it routes every entry into the loop through one copy-on-write of the local, so the elision knows the local unshared at the header and drops the calls inside unless the loop shares it. A loop writing the collection only on some iterations is left alone. The copy-on-write before a loop moves out through each enclosing loop whose every iteration enters it (the inner header dominates every edge back to the enclosing header), that writes the local only by those write-backs, and that never retains it or reads it whole other than for its length, a release or a question and its copy — so a loop nest gets one copy-on-write before its outermost loop, the elision answers the questions inside and those of later loops, and the stable-collections pass can record the nest's outer loop. The walk runs in the one pass over the loops as found; rerunning it would add a copy-on-write per round. The one copy added is a shared collection entering the outermost loop reached when no question of the loop the copy-on-write was made for would have run: the outermost loop runs no iteration, or that loop runs none each time it is entered. A uniqueness check on a whole local (`l[i].x = v`) is hoisted the same way, but only out of a loop that calls nothing but these questions, their copy paths and the runtime entry points that leave collection headers unchanged: that is the loop the stable-collections pass records once the checks inside are answered, so the hoisted local's header is read once before the loop. A loop making any other call keeps its check, since a local live across those calls costs more than the inline check. Natural loops come from `analysis/loops.rs`.
-   **Stable collections (`optimization/stable_collections.rs`)**: Run on every host body right after unshare check elision, branch threading and loop versioning. For each natural loop — outermost first — it records, on `Body::stable_collections`, each array or list local the loop indexes or takes the length of and leaves the header (data pointer, length, slot size) of unchanged: the local is assigned nothing in the loop but the identity round trip `t = move l … l = move t` an elided copy-on-write leaves, its storage neither starts nor ends there, and it is not a capture, a gpu-resident binding or address-taken; every call into the runtime names an entry point `runtime_fns::leaves_collection_headers_unchanged` allows or copies an array or a list (`runtime_fns::copies_collection`) whose element type is spelled out and is no class, trait or type parameter (`analysis::header_reach::runtime_call_leaves_headers`) — a copy-on-write or clone hands back its argument untouched or a fresh copy, retains elements and takes one from a count above one, so it writes no existing header and frees nothing, and the only program code it can run is an element's `clone`; the local that takes its result is rebound and so never recorded — a call to a function of the program passes `analysis::header_reach::HeaderReach::call_leaves_header`, no call goes through a vtable or launches a kernel, nothing is stored through a dereference, and no release or element store may run a drop hook (`type_facts::DropHookReach`). `analysis::stable_headers::StableHeaders` holds this per-collection predicate, which the loop-versioning pass asks too. `HeaderReach` is the one authority the pass and the verifier both ask about calls. It collects the local's aliases (every local a value of it may flow into, whole or through a part that may hold one, across the whole body) and allows a call to a function of the program only when the local is counted and owned — not a borrowed parameter, and no alias is borrowed, captured, gpu-resident or address-taken, and each definition of the local hands it a reference (a call's result, an aggregate, a move from a local holding its own, or a copy of a place the same block retained first) — and the call is handed no alias, nor a borrow of one whose type may hold the collection, and writes none. Two invariants make that sound. First, reference counting never takes a count from a local that lives across blocks: RC elision cancels a retain against a release only inside one block, and owned-argument transfer applies only to an owned argument named at the call and dying there. Second, a write to a collection header runs only on a place whose count the code naming it just checked: copy-on-write before every writer call at the caller's seam, and the `miri_rt_receiver_unique` check in a method that writes its receiver through another method. So a holder outside the local's aliases has a count of its own, the collection is shared while it lives, and a write through it copies or traps rather than changing the loop's header. Uniqueness is not a condition: only code that can reach the collection without a reference of its own could change its header while the loop runs. Each recorded loop gets a dedicated preheader, after any copy-on-write hoisted in front of it, and a collection is recorded only for the outermost loop it is stable in. Code generation (`codegen/cranelift/stable_headers.rs`) reads each recorded header once at the end of the preheader — null-guarded, the slot-size check run only when there is an element — and serves every index rooted at the local and every `Len` of it in the record's blocks from those values; it refuses a record whose preheader does not dominate its blocks. `--verify-mir` re-derives every record independently (`verify/stable_collections.rs`). `--emit mir` prints the records after the blocks.
-   **Loop versioning (`optimization/loop_versioning.rs`)**: Run on every host body after branch threading and before the stable-collections pass (a body already carrying a stable or in-bounds record is left alone, since copying moves the blocks they name). Two shapes of innermost loop are copied. One switches in its header on `i < n` or `i <= n` — `i` never negative, `n` an `int` the loop never writes — and indexes an array or list by `i` or by `x = i + c` (a constant `0 <= c <= 64` computed in the loop). The other is a two-pointer loop switching on `lo < hi` or `lo <= hi` — `lo` never negative and only stepped up by a constant, `hi` only stepped down by a constant, directly or through a copy — indexing a list by either pointer. In both the bound (`n` or `hi`) has no address taken, is not captured and is not simply the length of the list; the list is one `analysis::stable_headers` finds stable over the loop or a loop around it; the loop calls only runtime entry points `runtime_call_leaves_headers` clears, holds no `Phi` (nor do its exit blocks) and is small (at most 16 blocks, 64 statements, 4 lists). Its blocks are appended with in-loop edges led to the copies and exits unchanged, sharing every local and keeping every statement, storage marker and RC operation, and every entry into the loop goes through a chain of guards, one per list, each asking `bound + d <= L` of `L = Len(l)`: `Le(bound, L)` for `d = 0`, `Lt(bound, L)` for 1, `m = Sub(L, d); Le(bound, m)` above (a length is at least 0 and `d` small, so the subtraction cannot overflow and the guard cannot trap). `d` is the largest offset `c`, plus 1 for `i <= n`, and 1 for a two-pointer loop. The guard passes to the copy and fails to the original, checked loop, so a loop running past an end traps at the same iteration. Loops are chosen on the unmodified body and copied in header order, with the predecessor lists kept up to date as blocks are appended, so numbering is deterministic and a copy leaving straight into a later loop enters its guards.
-   **In-bounds accesses (`optimization/in_bounds.rs`)**: Run last among the MIR passes, on host bodies with a stable-collection record. A forward must-dataflow carries `n` holding the length of `l` (made by `n = Len(l)`, carried through a whole-local copy and through a copy-on-write or clone, `runtime_fns::preserves_length`; lost when either local is redefined or its storage ends, when `l` is released, or at any runtime call `analysis::header_reach::runtime_call_leaves_headers` does not clear — the same rule the stable-collections pass applies — and any call to a function of the program), the order `a + m <= b` for a margin `m >= 0` between integers of one type (made on the taken edge of `switchInt(c)` with `c = Lt(a, b)` (`m = 1`) or `c = Le(a, b)` (`m = 0`) computed in that block, or `c` a whole copy of such a comparison made there, the operands kept to the switch, and carried one step on to `a + m + m' <= x` for each `b + m' <= x` known there; `x = y + k` and `x = y - k`, `k` a constant at least 0, carry `y`'s margins to `x`, less `k` for the sum and unchanged for the difference, which also makes `x + k <= y`; lost with either side), and `i` in bounds of `l` (made wherever `i` gains a margin, when `i` is at least 0 — never negative, or ordered above a never-negative local — and `i + m <= L` with `m >= 1` for `L` holding `l`'s length; also on the taken edge of `i < n` with `n` the length and `i` never negative; lost with `i` or `l`'s length). Margins are about mathematical integers: integer `+` and `-` trap rather than wrap. `i <= n <= L` admits `i == L`; `i + 1` below `n` needs `n + 1 <= L`; `lo < hi` with `hi < L` and `lo` never negative keeps both pointers inside, and `hi = hi - k` keeps `hi`'s margin. Whether a local is never negative is decided once per body (`analysis::non_negative`), optimistically: every definition is a non-negative constant, a length, a copy of such a local, or a sum or product of such operands — sound only because integer `+` and `*` trap on overflow (`analysis::non_negative::INTEGER_ARITHMETIC_TRAPS_ON_OVERFLOW`, re-exported from `in_bounds`, which codegen's `emit_checked_int_op` reads); parameters, call results, captures, projected writes and address-taken locals never qualify, unsigned locals always do. Each proven root access `l[i]…` in a block a stable record of `l` covers goes on `Body::in_bounds` (printed by `--emit mir`), and code generation emits its element address without the compare and branch. A later pass that changes a block must drop its entries (the element-ABI pass does, by statement count); `--verify-mir` re-derives every entry with its own dataflow (`verify/in_bounds.rs`), which applies a switch's comparison only along its true edge.
-   **Unshared runtime writes (`verify/unshared_writes.rs`)**: Under `--verify-mir`, on every host body after unshare check elision, every argument a runtime entry point writes in place (`runtime_fns::writes_in_place`, which fails closed: an entry point no table classifies writes what it is handed) whose type a write copies first (`type_facts::unsharing::is_copied_on_write`) must be known, on every path into the call, to hold a block nothing else holds; each one that is not is a MER_MIR_014 finding. The proof is a forward must-dataflow of its own, sharing no code with the elision it checks beyond the runtime fact tables in `runtime_fns` (pinned by their own contract tests), over places and map entries. A place becomes known on the "no" edge of an `rc_is_shared` check, as the result of a clone or a copy-on-write entry point, when a struct just built or a known value nothing else names is moved into it, when it is moved out and straight back (the form an elided copy-on-write leaves), and after `miri_rt_receiver_unique` on it; a map entry becomes known when its lookup result is checked or a known value is stored under its key, and a later lookup under a key holding the same value (followed through whole-local copies) hands back a known place. A place is forgotten, with everything reached through it (an index matches any index), when it is retained, copied, moved elsewhere, stored into, released or its storage starts or ends, when an index or key local it depends on is reassigned, and when it is handed to a function of the program, a virtual call or a kernel, or to a runtime position that keeps it. Facts on a place the body does not hold privately — rooted at a parameter, a capture, a borrow, a gpu-resident binding or an address-taken local, or reached through a value shared by design such as a class instance — die wherever program code may run: such a call, a release that may run a drop hook, and a runtime call that calls a closure or may release an element with a hook. A runtime write keeps its own place known and forgets only what is reached through it, since the runtime keeps nothing it writes in place (the contract test `a_runtime_write_keeps_nothing_it_is_handed`). Arguments of a gpu-resident binding are exempt: residency's uploads and readbacks hand its host array to the runtime unchecked. Unreachable blocks are never reported.
-   **Unshare check elision (`optimization/unshare_elision.rs`)**: A write through a path asks of each value on it, outermost first, whether anything else holds it (`lowering/expression/unshare.rs`), and asks again on every later write. Run on every host body after RC elision, at every optimization level, this pass removes a check whose answer is already known to be no. A forward must-analysis carries the places known to hold a value nothing else holds: a place enters on the edge a check takes when it answers no, or when it is assigned a struct just built, a fresh collection clone (`runtime_fns::returns_unshared`) or an empty collection just built (`runtime_fns::allocates_collection`), what a collection's copy-on-write entry point hands back (`runtime_fns::is_copy_on_write`), or a value moved out of a whole local known unshared that nothing else reads — no retain, release, copy or second move of it anywhere in the body — and only while every place it is reached through is known too. So a path through a class instance never yields a fact, and neither does a place rooted at a parameter, a capture, a gpu-resident binding or an address-taken local, or indexed by an address-taken local. Retaining, releasing, copying, moving or passing a place to a call forgets every place it reaches, any index matching any index — except that a runtime entry point writing the place in place (`runtime_fns::writes_in_place`) and not taking it over keeps nothing it writes, so the place stays known and only what is reached through it is forgotten; writing a place forgets what it replaces and every place indexed by the local written — except that storing a fresh value into one element leaves the collection's other known elements known, since the collection alone still holds each. An answered check becomes a jump to its no-path, and a copy-on-write call on a place known unshared becomes a move of it into the call's destination, the blocks only its copy path reached are emptied and end in `unreachable`, and no block is renumbered; a run under the heap guard validates the written block at the check kept before it rather than at each removed one. Only the places a check asks about or a fresh value is stored into are tracked, each under a dense id, so the facts are bit sets, every statement's effect is resolved to masks once, and a worklist in reverse postorder revisits a block only when its entry state changed (`analysis/traversal.rs`).
-   **Values held as their bytes (`rc.rs`, `type_checker::value_class`)**: A struct, tuple, optional or enum whose members are all scalars or such values, at most 128 bytes, and a compiler-known vector of a scalar component (laid out as WGSL lays it out, so a `Vec3<f32>` spans 12 bytes aligned to 16 and a collection strides it by 16 — `ValueLayout::stride`), is held as its bytes rather than as a counted allocation — the one switch is `value_class::held_value_layout`. An optional held so is a one-byte presence tag with its payload beside it (`codegen/cranelift/inline_optionals.rs`); an enum held so is its tag word followed by one column per payload position (`codegen/cranelift/held_enums.rs`), placed by the same rule `codegen/cranelift/layout.rs::enum_payload_layout` places a counted enum's columns by, with the tag and the narrowest column a fixed 8-byte word rather than a pointer — so the two agree on 64-bit targets, which `tests/codegen/cranelift/layout.rs::test_held_enum_offsets_are_the_enum_columns` pins — unless it declares a drop hook, which keeps its identity, or type parameters, whose shared method bodies hand values over counted; an optional of a reference stays that reference's nullable pointer, and a layer around one stays boxed (`option_layout.rs`). `Body::value_layout` is the single answer the verifier (`verify/value_representation.rs`), Perceus (through `Body::is_counted`) and the backend read. Such a value lives in a stack slot of its frame, is copied whole wherever it is bound (there is no field-by-field rebuild and no unsharing of it), is passed to a Miri call as the address of the caller's own bytes — `value_arguments.rs` copies an argument first only when it is read from a local the same call writes as its destination or `out` argument, or through a projection not at a fixed offset of its root value local (a field of a counted holder, a member picked by a runtime index); a field of a value local is passed in place; `value_arguments::exposure_of` is the one rule the codegen backstop asks too; a callee copies on entry each value parameter it writes (`value_arguments::written_value_params`), and `verify/value_arguments.rs` checks that every call is left so and that no value is passed owned — and sits inline in whatever holds it: a class, struct or tuple field, a collection element, an enum payload, an optional's box or a closure's environment. `place_type.rs` reads the declared type a projected place reaches, which Perceus and the element ABI both ask.
-   **Copies read in place (`analysis/copies_read_in_place.rs`)**: A local holding a value as its bytes that is assigned once, by a copy out of a projected place (`t = code[pc]`, `t = s.field`), and is never written, address-taken or named by a terminator otherwise, is read in place when a forward must-analysis finds every read of it while the place still holds what was copied: no store through a projection, release, deallocation, call or kernel launch in between, no new value or storage change for a local the place is rooted at or indexed by, and no device buffer released. Code generation (`codegen/cranelift/value_locals.rs`) then binds such a local to the address of the place instead of copying the bytes into its slot, so a match on `code[pc]` reads the element's address once and each arm loads only the payload it binds, rather than loading every payload at the dispatch and holding them all across the branch.
-   **Element ABI (`src/mir/element_abi.rs`)**: The last pass before codegen. Every call that stores or looks up a collection element (`runtime_fns::element_positions`) is lowered with the element as one argument, which is how Perceus and `--verify-mir` read it. This pass rewrites each such argument into the address of the element's bytes (`Rvalue::Ref`) and the count of those bytes, taken from `type_checker::element_layout::element_layout`, read against the body's layout scope (`Body::layout_scope`: the program's type table and the body's open type parameters). The runtime lays the element out at its slot's full width, so List, Set and Map share one convention at every element width and no backend knows which arguments are elements. A call that hands an element back (`runtime_fns::returns_element_value`) is spelled the same way in reverse: the runtime writes the element into caller storage named by two trailing arguments — address and byte count — and returns nothing. A register-held destination becomes an `out` argument, a value held as its bytes is handed over by its address (`Rvalue::Ref`), and anything else goes through a register-sized slot assigned to the destination after the call. Collection literals ride the same calls: a list, set or map literal is lowered as its empty collection followed by one `push`/`add`/`set` call per element (`lowering/expression/collection_literal.rs`), so codegen only ever allocates an empty set or map and builds arrays alone from their elements.
-   **Closure ABI (`src/mir/closure_abi.rs`)**: Runs right after the element ABI, at the same hand-off. A parameter a `runtime` declaration types as a function takes the closure and then the address of a compiler-generated trampoline, `tramp(closure, a0, …, an, result)`, through which the runtime calls the closure with the address of each argument's bytes. The pass appends that address after each such argument as an `Operand::Function` naming `Symbol::closure_trampoline`, typed as the function of raw pointers it is, so codegen declares it like any other function address. The trampoline is named by its shape — per argument, the word it loads out of the slot or the slot's address itself, and the word it stores the result as — decided from the closure's parameter types against the collection element layout (`element_layout`): a value held as its bytes is passed by address, any other value as one word that must fill the slot exactly, and a result held as its bytes is refused. Which parameters carry a closure, and how the runtime calls it — arity, the `int` it reads the answer as, the collection whose element slots it passes — is `runtime_fns::closure_contract`. The type checker holds each `runtime` declaration to it (`type_checker/statements/runtime_closures.rs`) and this pass holds each call to it again at the types the call is made at, so a closure handed to a parameter of another type, such as the word a hash is made of, is left as it is. `runtime_fns::param_abi` is the one rule for how a declared runtime parameter travels (a word, an element, a closure), which the runtime import, the element ABI and this pass all read. GPU bodies are skipped.
-   **Source of a body (`Body::source`)**: The file a body's spans index, as a `SourceId`: the program's file is `SourceId::PROGRAM` and each imported module is numbered from 1 in the order the type checker finished loading it (`TypeChecker::imported_sources`). `LoweringContext::read_source_of` sets it for each declaration lowered, cloned and per-instantiation bodies included, and refuses, as an internal error, a declaration the type checker recorded in no file (`TypeChecker::declares_in_program` or `declaration_module_source`). A closure, a function-reference thunk or a kernel lowered inside a body takes its parent's (`read_source_like`). A default argument is written in the callee's file but lowered into the caller's body: it is lowered reading the callee's file, so what it bakes in and the closures it holds name that file, and when that file is another one the statements it adds to the caller are placed at the call. Every span of a body is therefore an offset into the body's own file. A body the compiler synthesizes with no text of its own (the equality and hash a container compares elements with) has none.
-   **Symbols (`src/mir/symbol.rs`)**: Every body is lowered under a `Symbol` — what it stands for: a function at its type arguments, a method of its owner, a closure, a GPU kernel — and `Symbol::link_name` is the one place its name is spelled. A Miri definition is linked as `miri.` followed by `.`-separated segments, with argument tokens and compiler-synthesized markers led by `$`: `miri.pick$int` is `pick<int>`, `miri.pick__int` a function written `pick__int`, `miri.Point.norm` a method, `miri.Box$String.$drop` a drop function, `miri.$lambda7` a lambda. A top-level function's root also names the module declaring it, one `$` segment per identifier of its import path: the program's own `helper` is `miri.helper`, the `helper` of `local.shapes` is `miri$local$shapes.helper`, so two modules may each declare a function of one name. Which module that is comes from a `ModuleId` — the program's own file, or a module a `use` loaded by its path — decided by how the file was loaded, so a module a `use` names `Main` is never the program. No identifier or type token contains `.` or `$`, so distinct symbols never share a link name, and none can take the name of the entry point `main` or of a `runtime` C function, both linked verbatim. A type argument's token comes from `src/mir/symbol/token.rs`; every type it cannot name (nested past `MAX_TOKEN_DEPTH`, or a closure type with type parameters of its own) spells one shared token, so a symbol carrying one is never claimed — lowering refuses such an instantiation with MER_MIR_017 first. GPU kernels, kernel data and string literals keep fixed compiler spellings, and `Symbol::wgsl_name` spells a body for WGSL with identifier characters only: a program function by its name, a function of an imported module as `m__`, each path identifier led by its length, `_` and its name (`m__6system4math_lattice_unit`), so a program function never takes a module function's WGSL name — one whose own name begins `m__`, or `__`, a prefix WGSL reserves, is spelled `m__0_` and its name, so no function's WGSL name begins `__`. The pipeline claims each symbol in a `SymbolTable` before lowering its body: claiming the same symbol again finds it already lowered, and a different symbol spelling a claimed name is refused with MER_MIR_018 as a guard over the grammar. A top-level function's symbol is claimed for its declaring statement; a second statement, or any statement reaching a symbol some other path already claimed, is an internal error rather than a body silently dropped. The WGSL spelling is not injective, so `src/mir/gpu_names.rs` claims every kernel and every helper GPU code reaches a second time, in a table keyed on that spelling, and refuses two definitions sharing one with MER_MIR_018. How a call is compiled — a `runtime` export, an `intrinsic`, or a program function — is what the declaration its name resolved to where it was written says (`TypeChecker::callee_kind`), never its spelling; which function it is, module included, is recorded the same way (`TypeChecker::declared_callee`), and the module each top-level function declaration comes from by statement, the program's own recorded as such (`TypeChecker::declaring_module`); a declaration with no recorded module is an internal error, never assumed to be the program's.
-   **SSA Form (`src/mir/ssa/`)**: Infrastructure to convert MIR into Static Single Assignment form (using Phi nodes) for advanced analysis, and back out of it.
-   **Dominator Analysis**: Computes dominator trees used by SSA and optimization passes.
-   **GPU Metadata (`backend/`)**: Extensions to the MIR to support heterogeneous execution models, handling GPU kernel limits, barriers, and thread indices.

## Monomorphization

A generic function or generic-class method is lowered once per instantiation, with its substitution (`LoweringContext::generic_subs`) applied to every recorded type. What such a body reaches is recorded on the `Body` rather than recovered from mangled symbols:

-   `generic_function_calls` — each generic function it calls, at the types the call pins. The pipeline lowers those in a worklist.
-   `residency_function_calls` — each call it retargets to a body specialized for the gpu-resident buffers it passes, with the function that body is lowered from. The pipeline lowers those after the generic worklist.
-   `generic_class_instantiations` — each generic class it names only through its substitution (`Box<T>` inside `via_box<T>` lowered at `String`). The pipeline adds these to the type checker's instantiation registry, then emits the methods they call, repeating until nothing new is reached. Codegen reads the same registry for per-instantiation drop functions and element-method thunks.

## Design Principles

1.  **Explicit Control Flow**: All loops and conditionals are desugared into simple conditional and unconditional branches.
2.  **Visitor Pattern**: Extensively utilizes immutable and mutable Visitor traits to traverse and transform the MIR graph safely.
3.  **Backend Agnostic**: The MIR is optimized specifically for Miri's semantics but remains decoupled from the final target architecture (Cranelift, LLVM, SPIR-V).
