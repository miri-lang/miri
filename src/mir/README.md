# Mid-Level Intermediate Representation (MIR)

The `mir` module defines the Mid-Level Intermediate Representation, a Control-Flow Graph (CFG) based representation of Miri programs used for advanced analysis and optimization.

## Overview

While the Abstract Syntax Tree (AST) represents the syntactic structure of code, it implicitly encodes control flow (like loops and branches). MIR flattens this structure into explicit jumps between Basic Blocks, making dataflow analysis, optimization, and code generation much simpler.

## Core Concepts

-   **Basic Block (BB)**: A linear sequence of statements with a single entry point and a single exit point (a `Terminator`).
-   **Terminator**: The instruction at the end of a block that dictates control flow (e.g., `Goto`, `SwitchInt`, `Return`, `Call`).
-   **Locals (`_0`, `_1`, etc.)**: All variables and temporaries are flattened into an indexed array of Locals. `_0` is always the return value.
-   **Places and Rvalues**: Assignments take the form of `Place = Rvalue`, meaning a computational result (`Rvalue`) is written into a memory location (`Place`).

## Architecture

-   **Lowering (`src/mir/lowering/`)**: Translates the checked AST into the MIR format.
    -   **Instance demand (`instance_demand.rs`, `vtable_demand.rs`)**: Which methods of a generic class instance are compiled. A method a lowered body calls by name is compiled at its instance; one only a vtable slot or a container's element thunk names is compiled only where the checker's obligations hold there (`ImpliedMethodVerdicts`), and withheld elsewhere, its slot filled with the runtime trap. `vtable_demand.rs` decides which slots a program reads at all.
-   **Instantiation algebra (`src/mir/instantiation/`)**: The one home of the rules for generic instantiation that lowering and codegen share — what a written type argument denotes, how a substitution rewrites a type, the type a member (a field or an enum payload) has at an instantiation (`member_type_at`, `field_types`), which arguments get a per-instantiation body, (`shape.rs`) a type's constructor parts, how deep an instance nests and which parameters it leaves open, and (`inherited.rs`) what a class inherits at an instantiation through its `extends` chain. Lowering re-exports these under its old paths.
-   **Dispatch data (`src/mir/dispatch/`)**: The settled shape of dynamic dispatch as data: the shared `VtableLayout`, the `VtableInstance` a constructed instance points at, the `VtableFills` each vtable is written with, and the methods a container asks of its elements. How a slot's target is resolved stays with lowering's method dispatch.
-   **Type facts (`src/mir/type_facts/`)**: The read-only `TypeFacts` the pipeline builds once lowering has settled every instantiation and hands to the CPU backend — the one seam through which codegen reads the program's types (a `make audit` gate and `tests/codegen/layer_boundary.rs` keep codegen from naming the type checker or MIR lowering). It holds the type definitions (re-exported as data), the method-body instantiation registry and the vtable fills, and answers the rules the backend needs by delegating to their one implementation: a field's type at an instantiation, a type's drop hook and `clone`, the traits it implements and the methods a container asks of its elements. `drop_instantiations.rs` settles the separate set of instantiations a drop thunk is emitted for: every concrete instantiation a compiled host body holds (locals, closure captures, struct and class constructions, aliases read through), closed over the fields and payloads those store, refused as polymorphic recursion when a field nests its own type past the instance depth bound.
-   **Residency readbacks (`src/mir/residency/`)**: A required pass, run on every host body after lowering and before Perceus, that reads a `gpu`-resident binding's device buffer back into its host array before each host read that could otherwise see stale values. A forward dataflow tracks, per device handle, whether the host array may lag the device: a read every path reaches behind reads back unconditionally, a read only some paths reach behind (the first read in a loop after a launch) tests a flag the pass keeps for the handle, and a read no path reaches behind gets nothing. Each readback first gives the binding a host array of its own, so earlier host copies keep their values. `verify::verify_cross_residency_readback` independently checks the result under `--verify-mir`.
-   **Equality and hashing (`lowering/expression/structural_equality.rs`, `structural_hash.rs`)**: `==` on a struct, enum or optional is lowered to a walk over the parts it compares, calling the `equals` a type declares where it has one. `x.hash()` on a type that declares no `hash` is lowered (`lowering/derived_hash_call.rs`) to a mirror walk over the same parts, so two values `==` calls equal hash alike; an operator method a non-class type answers through its operator (`lowering/derived_operator_call.rs`) is lowered as that operator — `equals` as `==`, `concat` as `+`, `repeat` as `*`, `compare` as `(a > b) - (a < b)` over operands evaluated once; a kind `==` compares as one machine word hashes that word. A set or map matched through an `equals` callback is also handed a hash callback: `dispatch::element_hash_symbol` names one per element type, the pipeline lowers it from the same walk (`lowering/element_equality.rs`), and codegen registers it beside the equality.
-   **Optimization (`src/mir/optimization/`)**: A suite of passes (`SimplifyCfg`, `ConstantPropagation`, `CopyPropagation`, `DeadCodeElimination`, `Perceus RC`) that transform and optimize the MIR inplace.
-   **Owned parameters (`optimization/owned_params.rs`)**: A call lends its managed arguments by default — the callee reads the caller's reference and never releases it. Run once over the whole program after the residency readbacks and before Perceus, this pass makes a parameter *owned* when its only use is one binding to a local in the entry block (`var items = start`). Everything else stays borrowed: an `out` parameter; a vector, which a collection stores inline; a gpu-resident buffer, as the parameter or as the binding; a type whose release may run a drop hook anywhere inside it (`mir::type_facts::DropHookReach` — elements, options, tuples, fields, payloads, any subclass, and conservatively every trait-typed value, closure and type parameter), since owning it would move where the hook runs; a type naming a type parameter; a binding that dies in the entry block, which costs nothing borrowed; a body whose entry block a branch returns to, where the binding would run more than once; and any function that is not a plain top-level host function compiled for one instantiation, is captured into a closure, is named as a value, is called from a GPU body or a compiler-synthesized caller, is called at another arity, is never called, or is lowered into more than one body. The binding becomes a move out of the parameter, `Body::owned_params` records it, and every call to the function passes that argument `ArgMode::Owned`. Perceus retains each owned argument before the call and does not retain the parameter in the callee; RC elision cancels that retain against the caller's release of a local that dies right after the call, so a callee writing its binding finds it unshared and writes in place instead of copying. `--verify-mir` tracks an owned parameter from one reference on entry, consumes an owned argument at the call, and checks across the program that every call's modes match its callee's `owned_params`, and that a function taking a parameter over has one body, is named only as a call's callee and is called by no GPU body.
-   **Borrowed locals (`optimization/local_borrows.rs`)**: Run inside Perceus, before it places any retain. A managed local defined only by copies of a projected place reached from a local the body owns — not a parameter or a capture — through value steps alone (an element of a `List` or `Array`, a field of a struct, tuple or optional, an enum's payload; never a class field, which a method can clear unseen) borrows what it reads, the way a body borrows a parameter: no retain at the read, no release at its `StorageDead`. It must run no drop hook and hold no device buffer, and must never be rebound, released by hand, made a call's result, merged in a phi, handed to a runtime entry point that keeps it or asks whether it is shared, or passed `out`. Unless its type is a reference by design (a class, or a trait some class implements and only reference classes do), it must never be written through, nor handed to any callee other than a runtime entry point that only reads it (`runtime_fns::only_reads_argument`, an allow-list): a callee writes a parameter in place when nothing else holds it, and a borrowed value's count is its owner's. On every path from a definition to the end of its storage — reaching the body's end first refuses it — its root, and a borrowed parent's owners for a borrow read out of another, is only read through a projection, retained through one, or lent by copy to such a reader. Escapes stay funded as for a borrowed parameter: a copy into a store, a return, an aggregate or a capture, a move, and an owned argument are each retained. `Body::borrowed_locals` maps each borrow to every owner keeping what it holds alive; RC elision never cancels an owned argument's retain against a borrow, never elides the retain of a local a borrow relies on, and never elides a pair copying a borrow. `verify/local_borrows.rs` checks every record again from the final MIR under `--verify-mir`, with its own access classification — a record that holds leaves the local untracked, one that does not is a violation; the value-step and reference-by-design predicates are shared with the inference.
-   **Index numbering (`optimization/index_numbering.rs`)**: Lowering computes an index written as an expression (`l[i + 1]`) into a temp of its own at every use, so two writes to one element reach it through two places. Run just before unshare check elision, this pass renames every index through a temp to the earliest temp holding the same value: a temp written once by arithmetic on locals and literals, whose storage and address the body never touches and none of whose operands has its address taken. A forward must-analysis carries the temps whose expression still has their value; a write to an operand, or a change of its storage, removes them.
-   **Loop unsharing (`optimization/loop_unsharing.rs`)**: Run after index numbering and before unshare check elision. For each natural loop with a block that hands a whole collection local to its copy-on-write entry point on every iteration (it dominates every back edge), and that writes the local no other way than by those calls' write-backs, it routes every entry into the loop through one copy-on-write of the local, so the elision knows the local unshared at the header and drops the calls inside unless the loop shares it. A loop writing the collection only on some iterations is left alone; the one copy added is a shared collection entering a loop that runs no iteration. A uniqueness check on a whole local (`l[i].x = v`) is hoisted the same way, but only out of a loop that calls nothing but these questions, their copy paths and the runtime entry points that leave collection headers unchanged: that is the loop the stable-collections pass records once the checks inside are answered, so the hoisted local's header is read once before the loop. A loop making any other call keeps its check, since a local live across those calls costs more than the inline check. Natural loops come from `analysis/loops.rs`.
-   **Stable collections (`optimization/stable_collections.rs`)**: Run on every host body right after unshare check elision. For each natural loop — outermost first — it records, on `Body::stable_collections`, each array or list local the loop indexes or takes the length of and leaves the header (data pointer, length, slot size) of unchanged: the local is assigned nothing in the loop but the identity round trip `t = move l … l = move t` an elided copy-on-write leaves, its storage neither starts nor ends there, and it is not a capture, a gpu-resident binding or address-taken; every call names a runtime entry point `runtime_fns::leaves_collection_headers_unchanged` allows, nothing is stored through a dereference, and no release or element store may run a drop hook (`type_facts::DropHookReach`). Uniqueness is not a condition: only a call or a hook could change any alias's header while the loop runs. Each recorded loop gets a dedicated preheader, after any copy-on-write hoisted in front of it, and a collection is recorded only for the outermost loop it is stable in. Code generation (`codegen/cranelift/stable_headers.rs`) reads each recorded header once at the end of the preheader — null-guarded, the slot-size check run only when there is an element — and serves every index rooted at the local and every `Len` of it in the record's blocks from those values; it refuses a record whose preheader does not dominate its blocks. `--verify-mir` re-derives every record independently (`verify/stable_collections.rs`). `--emit mir` prints the records after the blocks.
-   **Unshare check elision (`optimization/unshare_elision.rs`)**: A write through a path asks of each value on it, outermost first, whether anything else holds it (`lowering/expression/unshare.rs`), and asks again on every later write. Run on every host body after RC elision, at every optimization level, this pass removes a check whose answer is already known to be no. A forward must-analysis carries the places known to hold a value nothing else holds: a place enters on the edge a check takes when it answers no, or when it is assigned a struct just built, a fresh collection clone (`runtime_fns::returns_unshared`), what a collection's copy-on-write entry point hands back (`runtime_fns::is_copy_on_write`), or a value moved out of a whole local known unshared that nothing else reads — no retain, release, copy or second move of it anywhere in the body — and only while every place it is reached through is known too. So a path through a class instance never yields a fact, and neither does a place rooted at a parameter, a capture, a gpu-resident binding or an address-taken local, or indexed by an address-taken local. Retaining, releasing, copying, moving or passing a place to a call forgets every place it reaches, any index matching any index; writing a place forgets what it replaces and every place indexed by the local written — except that storing a fresh value into one element leaves the collection's other known elements known, since the collection alone still holds each. An answered check becomes a jump to its no-path, and a copy-on-write call on a place known unshared becomes a move of it into the call's destination, the blocks only its copy path reached are emptied and end in `unreachable`, and no block is renumbered; a run under the heap guard validates the written block at the check kept before it rather than at each removed one. Only the places a check asks about or a fresh value is stored into are tracked, each under a dense id, so the facts are bit sets, every statement's effect is resolved to masks once, and a worklist in reverse postorder revisits a block only when its entry state changed (`analysis/traversal.rs`).
-   **Values held as their bytes (`rc.rs`, `type_checker::value_class`)**: A struct, tuple or optional whose members are all scalars or such values, at most 128 bytes, is held as its bytes rather than as a counted allocation — the one switch is `value_class::held_value_layout`. An optional held so is a one-byte presence tag with its payload beside it (`codegen/cranelift/inline_optionals.rs`); an optional of a reference stays that reference's nullable pointer, and a layer around one stays boxed (`option_layout.rs`). `Body::value_layout` is the single answer the verifier (`verify/value_representation.rs`), Perceus (through `Body::is_counted`) and the backend read. Such a value lives in a stack slot of its frame, is copied whole wherever it is bound or passed (there is no field-by-field rebuild and no unsharing of it), and sits inline in whatever holds it: a class, struct or tuple field, a collection element, an enum payload, an optional's box or a closure's environment. `place_type.rs` reads the declared type a projected place reaches, which Perceus and the element ABI both ask.
-   **Element ABI (`src/mir/element_abi.rs`)**: The last pass before codegen. Every call that stores or looks up a collection element (`runtime_fns::element_positions`) is lowered with the element as one argument, which is how Perceus and `--verify-mir` read it. This pass rewrites each such argument into the address of the element's bytes (`Rvalue::Ref`, or the operand itself for an inline vector) and the count of those bytes, taken from `type_checker::element_layout::element_layout`, read against the body's layout scope (`Body::layout_scope`: the program's type table and the body's open type parameters). The runtime lays the element out at its slot's full width, so List, Set and Map share one convention at every element width and no backend knows which arguments are elements. A call that hands an element back (`runtime_fns::returns_element_value`) is spelled the same way in reverse: the runtime writes the element into caller storage named by two trailing arguments — address and byte count — and returns nothing. A register-held destination becomes an `out` argument, an inline vector is built with zero components and its storage handed over, a value held as its bytes is handed over by its address (`Rvalue::Ref`), and anything else goes through a register-sized slot assigned to the destination after the call. Collection literals ride the same calls: a list, set or map literal is lowered as its empty collection followed by one `push`/`add`/`set` call per element (`lowering/expression/collection_literal.rs`), so codegen only ever allocates an empty set or map and builds arrays alone from their elements.
-   **Symbols (`src/mir/symbol.rs`)**: Every body is lowered under a `Symbol` — what it stands for: a function at its type arguments, a method of its owner, a closure, a GPU kernel — and `Symbol::link_name` is the one place its name is spelled. A Miri definition is linked as `miri.` followed by `.`-separated segments, with argument tokens and compiler-synthesized markers led by `$`: `miri.pick$int` is `pick<int>`, `miri.pick__int` a function written `pick__int`, `miri.Point.norm` a method, `miri.Box$String.$drop` a drop function, `miri.$lambda7` a lambda. A top-level function's root also names the module declaring it, one `$` segment per identifier of its import path: the program's own `helper` is `miri.helper`, the `helper` of `local.shapes` is `miri$local$shapes.helper`, so two modules may each declare a function of one name. Which module that is comes from a `ModuleId` — the program's own file, or a module a `use` loaded by its path — decided by how the file was loaded, so a module a `use` names `Main` is never the program. No identifier or type token contains `.` or `$`, so distinct symbols never share a link name, and none can take the name of the entry point `main` or of a `runtime` C function, both linked verbatim. A type argument's token comes from `src/mir/symbol/token.rs`; every type it cannot name (nested past `MAX_TOKEN_DEPTH`, or a closure type with type parameters of its own) spells one shared token, so a symbol carrying one is never claimed — lowering refuses such an instantiation with MER_MIR_017 first. GPU kernels, kernel data and string literals keep fixed compiler spellings, and `Symbol::wgsl_name` spells a body for WGSL with identifier characters only: a program function by its name, a function of an imported module as `m__`, each path identifier led by its length, `_` and its name (`m__6system4math_lattice_unit`), so a program function never takes a module function's WGSL name — one whose own name begins `m__`, or `__`, a prefix WGSL reserves, is spelled `m__0_` and its name, so no function's WGSL name begins `__`. The pipeline claims each symbol in a `SymbolTable` before lowering its body: claiming the same symbol again finds it already lowered, and a different symbol spelling a claimed name is refused with MER_MIR_018 as a guard over the grammar. A top-level function's symbol is claimed for its declaring statement; a second statement, or any statement reaching a symbol some other path already claimed, is an internal error rather than a body silently dropped. The WGSL spelling is not injective, so `src/mir/gpu_names.rs` claims every kernel and every helper GPU code reaches a second time, in a table keyed on that spelling, and refuses two definitions sharing one with MER_MIR_018. How a call is compiled — a `runtime` export, an `intrinsic`, or a program function — is what the declaration its name resolved to where it was written says (`TypeChecker::callee_kind`), never its spelling; which function it is, module included, is recorded the same way (`TypeChecker::declared_callee`), and the module each top-level function declaration comes from by statement, the program's own recorded as such (`TypeChecker::declaring_module`); a declaration with no recorded module is an internal error, never assumed to be the program's.
-   **SSA Form (`src/mir/ssa/`)**: Infrastructure to convert MIR into Static Single Assignment form (using Phi nodes) for advanced analysis, and back out of it.
-   **Dominator Analysis**: Computes dominator trees used by SSA and optimization passes.
-   **GPU Metadata (`backend/`)**: Extensions to the MIR to support heterogeneous execution models, handling GPU kernel limits, barriers, and thread indices.

## Monomorphization

A generic function or generic-class method is lowered once per instantiation, with its substitution (`LoweringContext::generic_subs`) applied to every recorded type. What such a body reaches is recorded on the `Body` rather than recovered from mangled symbols:

-   `generic_function_calls` — each generic function it calls, at the types the call pins. The pipeline lowers those in a worklist.
-   `residency_function_calls` — each call it retargets to a body specialized for the gpu-resident buffers it passes, with the function that body is lowered from. The pipeline lowers those after the generic worklist.
-   `generic_class_instantiations` — each generic class it names only through its substitution (`Box<T>` inside `via_box<T>` lowered at `String`). The pipeline adds these to the type checker's instantiation registry, then emits the methods they call, repeating until nothing new is reached. Codegen reads the same registry for per-instantiation drop functions and element-method thunks.

## Design Principles

1.  **Explicit Control Flow**: All loops and conditionals are desugared into simple conditional and unconditional branches.
2.  **Visitor Pattern**: Extensively utilizes immutable and mutable Visitor traits to traverse and transform the MIR graph safely.
3.  **Backend Agnostic**: The MIR is optimized specifically for Miri's semantics but remains decoupled from the final target architecture (Cranelift, LLVM, SPIR-V).
