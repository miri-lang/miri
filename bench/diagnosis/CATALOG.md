# Mechanisms catalog

Every mechanism a benchmark loss has been traced to, with the cells that
showed it and where the work stands. A new diagnosis starts here: a loss
whose evidence matches an entry is that entry until shown otherwise. An entry
is added by the engineer who names a mechanism in a cell's `DIAGNOSIS.md`, in
the same change that files the work.

| Mechanism | What it is | Cells | Evidence | Status |
|---|---|---|---|---|
| `sort-quadratic` | A sort that makes n² comparisons: the native `List.sort`/`Array.sort` was an insertion sort, and `sorted_by` a bubble sort. | list-sort | 250000 numbers: 54 s against 50 ms in C, all in `numbers.sort()`; 499500 comparator calls for 1000 elements | Fixed: `d24a122a` (native sort), `9898ff07` (`sorted_by`) |
| `string-append-copies` | `text = text + piece` allocates a new string and copies all of `text`, though `text` is the only reference to it, so building a string piece by piece is quadratic. | string-builder (blocked), json-roundtrip | Doubling the pieces quadruples the time; writing a JSON document back: 140 ms at 3500 records, 8577 ms at 35000; json-roundtrip at S is 94× C, with 52 % of its samples in `memmove` and `String.concat` its hottest Miri function | Filed |
| `cow-copy-per-step` | A list passed to a function that writes into it (`bodies = advance(bodies, dt)`, `var bodies = start` inside) is copied in full on the first write, though the caller's value dies at the call; the copy shares every element, so each element written is then boxed afresh. | nbody | 7 allocations per step for 5 bodies: one list, one buffer, one per body (10.5 M at 1.5 M steps); `MIRI_RC_STATS` shows no runtime copy-on-write, so the copy is the eager `miri_rt_list_clone` on the write path; doing the step in place removes every per-step allocation and 21 % of the time | Filed |
| `shared-check-per-field-write` | Every write into a field of a list element asks the runtime twice, out of line, whether the list and the element are shared, and asks again on the next write though nothing in between could have shared them. | nbody | 18 `miri_rt_rc_is_shared` calls per body pair in the step loop; 26 % of the samples of an in-place variant with no copies | Filed (two tasks: inline the check; drop the repeated ones) |
| `growth-without-capacity` | A list whose final length the algorithm knows grows by doubling, because Miri has no way to reserve it; on the system allocator the freed buffers of each growth inflate the peak. | sieve (hot), list-sort, wordfreq, json-roundtrip, k-nucleotide | sieve hot mode peaks at 140 MB against 17 MB cold; a C program growing a buffer the same way peaks at 146 MB | Filed |
| `struct-value-on-the-heap` | A small struct of primitive fields, returned from a function by value, is allocated on the heap and freed, though it is a bitwise-copy value. | ray-tracer | About 47 allocations per pixel (471797 at 100 × 100); `malloc` and `free` lead the hot run's profile; 17 × C at S | Filed |
| `float-spilled-across-calls` | A float that is live across any call in its function is kept in a stack slot for its whole live range, so a loop-carried accumulator is stored and reloaded on every iteration, even when the loop itself makes no call. | spectral-norm | `sum` is loaded and stored per inner iteration (`ldur`/`stur q4, [sp, #8]` on aarch64); the same loop in a function with no calls keeps it in a register and runs 33 % faster; inlining the per-element call alone changes nothing | Filed |
| `overflow-check-codegen` | An overflow-checked add or multiply takes four instructions where a flag branch takes two, and the zero and MIN/-1 checks on a division by a literal constant are emitted and never folded. | spectral-norm | Six checks and two constant-false branches in the per-element index arithmetic, which takes 65 % of the samples; C with `-ftrapv` pays 26 % for the same checks | Constant divisors fixed (no measurable time: the branches were predicted); the flag lowering is Cranelift's |
